# Note to JSON — Obsidian 插件设计规格

- 日期：2026-10-29
- 状态：已实现（见第 11、12 节）
- 标识：插件 id 与显示名已由 `markdown-tidy` / `Markdown Tidy` 改为 `note-to-json` / `Note to JSON`，版本 0.0.1
- 定位：纯本地 Markdown 排版规范化插件，零外部依赖、零网络请求

## 1. 目标

在 Obsidian 内向用户提供四条命令：

1. **格式化（Format）**：把 Markdown 笔记的结构性排版噪声规范化（标题、列表、空行、代码块、表格）。
2. **简化（Simplify）**：在不动语义的前提下压缩空白，让笔记更紧凑。
3. **格式化 JSON**：把选中的 JSON 或整篇 JSON 文件重排为 2 空格缩进的易读结构。
4. **压缩 JSON**：把 JSON 压缩成单行，便于嵌入配置或命令。

四条命令都要支持自定义快捷键，且全部处理**只作用于文本排版，不改变正文内容含义**。

## 2. 非目标

- 不做 AI 改写、不做摘要、不做内容压缩。
- 不做中文全半角转换、不做中英文之间自动加空格、不做有序列表重新编号。
- 不做保存时自动格式化、不做全库批量格式化。
- JSON 不做宽松修复（去注释、去尾逗号、单引号），不做键名排序，不做图形化树视图。
- 不提供插件内的按键录制/自定义输入框（自定义能力交给 Obsidian 原生快捷键设置）。
- 不提供自动化测试用例（由用户与前端/编辑器直接联调验收）。

## 3. 关键决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 实现路线 | 行级状态机 + 纯文本规则管线 | 确定性可验证；不用 AST 序列化，避免改写 wikilink / callout / 注释 |
| 技术栈 | TypeScript + esbuild，external `obsidian` | 与 Obsidian 官方示例工程一致 |
| 写回方式 | `editor.transaction` 单次变更 | 保留 Ctrl+Z 一步回滚与文档历史 |
| 规则可配置性 | 规则以声明式数组定义，设置页自动渲染开关 | 新增规则不需要改 UI 代码 |
| 规则粒度 | 格式化 11 条、简化 5 条，逐条可开关 | 用户可按笔记类型关闭有风险的规则 |
| JSON 实现方式 | 自写 tokenizer 重排空白，不经过 `JSON.stringify` | stringify 会把大整数丢精度、把 `1e21` 改写为 `1e+21`、把 `\/` 与 `\uXXXX` 解密重组 |

## 4. 架构

### 4.1 目录结构

```
manifest.json          # id: note-to-json, minAppVersion 1.4.0
package.json           # main: main.js；scripts: dev / build
tsconfig.json
esbuild.config.mjs
versions.json
src/
  main.ts              # 插件入口：命令注册、默认热键、设置装载
  settings.ts          # TidySettings 类型 + DEFAULT_SETTINGS
  settingsTab.ts       # 设置面板（规则开关自动渲染）
  core/segment.ts      # 保护区切分状态机
  core/pipeline.ts     # formatMarkdown / simplifyMarkdown 入口
  core/rules.ts        # 格式化规则 F1–F11 声明式定义
  core/compact.ts      # 简化规则 S1–S5 声明式定义
  core/text.ts         # 行工具：splitLines / 前导空白宽度 / 占位符保护
  core/json.ts         # JSON 校验 + tokenizer 重排（formatJson / compressJson）
```

### 4.2 数据流

```
命令触发
  → 读取选区/全文，扩展为整行区间
  → segment()：从文档首行扫描至区间起点，得到初始保护态；
                再扫描区间，产出每行的 protected 标记
  → 行内保护：把行内代码 `x`、[[wikilink]]、![](embed)、URL 替换为占位符
  → 按规则顺序执行已启用的规则（跳过 protected 行）
  → 还原占位符
  → 与原文本比对：相同则 Notice「已是规范格式」；不同则 editor.transaction 写回
  → 恢复光标，可选 Notice「已格式化 / 已简化」
```

JSON 命令走独立分支，不经过 markdown 规则管线：

```
JSON 命令 / 右键菜单
  → 有选区取选区原文（不扩行），无选区取全文
  → JSON.parse 仅判定合法性（失败：Notice 行列与片段 + console.error，原文不写回）
  → tokenizer 重排空白：格式化 2 空格 / 压缩单行，字面量原样输出
  → editor.transaction 写回命中的区间
```

### 4.3 保护区切分（segment.ts）

按行维护状态，以下区间整行标记 `protected = true`，所有规则跳过：

1. **frontmatter**：第 1 行为 `---` 时，直到下一个 `---` 或 `...` 行（含边界行）。
2. **围栏代码块**：起始行匹配 `^ {0,3}(`{3,}|~{3,})(.*)$`，用同字符、长度不小于起始标记的闭合行结束（含边界行）。
3. **数学块**：`$$` 独占行开始，至下一个 `$$`（含边界行）。
4. **HTML 注释块**：`<!--` 开始，至 `-->`（含边界行）。

行内保护（仅对非 protected 行）：用 `\u0000<index>\u0000` 形占位符替换以下片段，规则执行完毕后按索引还原：

- 行内代码：`` `...` ``、``` ``...`` ```
- wikilink 与嵌入：`[[...]]`、`![[...]]`
- 图片/链接目标：`](...)` 内的括号内容
- 裸 URL：`https?://` 起始的连续非空白字符

### 4.4 为什么需要「从文档首行预热状态」

只扫描选区时，若选区以 `# 标题` 开头而它上方 3 行有一个未闭合的围栏，则选区内的「标题」其实是代码内容。因此 segment 必须先空跑到区间起点，再正式产出标记。该行为在设计中是硬性要求。

## 5. 规则规格

### 5.1 格式化规则（执行顺序固定为 F1→F11）

| ID | 规则 | 输入 | 输出 | 默认 |
| --- | --- | --- | --- | --- |
| F1 | 标题规范化 | `#标题`、`##   标题  ` | `# 标题`、`## 标题` | 开 |
| F2 | 行尾空白清理 | `文字   ` | `文字` | 开 |
| F3 | 连续空行压缩 | 3 个连续空行 | 1 个空行 | 开 |
| F4 | 无序列表符号统一 | `* 项`、`+ 项`、`* [ ] 任务` | `- 项`、`- [ ] 任务` | 开 |
| F5 | 强调符统一 | `__粗__`、`_斜_` | `**粗**`、`*斜*` | 开 |
| F6 | 列表缩进统一 | 4 空格缩进的子项 | 2 空格/级 | 开 |
| F7 | 标题层级递进 | `# A` 后紧跟 `### B` | `## B` | 开 |
| F8 | 标题前后空行 | 标题上一行有正文、下一行有正文 | 上下各 1 空行 | 开 |
| F9 | 块级元素间隔 | 段落紧贴代码块 / 表格 | 之间插入 1 空行 | 开 |
| F10 | 表格列对齐 | 未对齐的表格 | 按列内最大字符宽补齐 | 开 |
| F11 | 补代码块语言 | 围栏起始行无语言标识 | 补设置中指定的语言 | 关 |

规则细节与边界：

- **F1**：仅当行首 `#{1,6}` 后不是空格时插入 1 个空格；多个空格压为 1；标题行尾空白由 F2 处理。保护区内行跳过。
- **F3**：只在非 protected 行之间压缩；文档首尾空行不在此规则删除（交给 simplify）。
- **F3 / F8 / F9 的幂等约束**：F8、F9 插入空行时必须实现为「确保恰好 1 个空行」（若已存在空行则吸收多余，而非再插一个），因此三条规则任意顺序执行结果一致，不会出现相邻双空行。
- **F4**：仅匹配 `^(\s*)([*+-])\s+`，`-` 保持不变；`*text*` 这类无空格强调不被误判。
- **F5**：`__x__` → `**x**`；`_x_` → `*x*`。要求两侧为词边界，`snake_case` 与 `file_name_x` 不动；占位符保护的片段不参与。
- **F6**：前导空白宽度先按「空格 = 1、Tab = 4」折算成数值；扫描全文列表行的前导宽度集合，取最小正宽度作为单位 `U`；每行层数 `level = floor(width / U)`，输出 `2 * level` 个空格（Tab 一并替换为空格）。代码块内跳过。整篇只有单层列表时 `U` 即该层宽度，结果等价于不变。
- **F7**：记录上一个标题层级 `prev`，若当前层级 `cur > prev + 1` 则改为 `prev + 1`（并以其为新 `prev`）。首个标题不强制为 `#`，保留原层级。保护区内的 `#` 行不参与。
- **F8**：标题行前后强制恰好 1 个空行；文档首行标题前不加；标题行后紧跟另一个标题时也只保留 1 个空行。
- **F9**：围栏代码块 / 表格块的起始行前若紧邻正文，插入 1 空行；结束行后同理。表格识别条件：连续行 trim 后以 `|` 开头、且至少 2 行、第 2 行匹配分隔行 `^\|?[\s:-]+\|`。
- **F10**：列宽按 **Unicode 字符数** 计算（CJK 视为 1 字符，不按双宽处理，已知局限）；分隔行长度 = 列宽（不少于 3），保留 `:---` / `---:` / `:---:` 对齐标记；含 `\|` 转义的行按转义后宽度计算。
- **F11**：仅当设置项 `codeBlockDefaultLang` 非空时生效，且只补完全空的语言位（`` ``` `` → `` ```text ``）。

### 5.2 简化规则（执行顺序固定为 S1→S5）

| ID | 规则 | 说明 | 默认 |
| --- | --- | --- | --- |
| S1 | 行尾空白清理 | 同 F2 | 开 |
| S2 | 连续空行压为 1 | 全文（保护区外）最多 1 个空行 | 开 |
| S3 | 列表项之间空行删除 | 同一列表块内相邻项之间的空行删除（判据：空行上下最近的非空行都以列表标记 `^\s*([-+*]|\d+\.)\s` 开头） | 开 |
| S4 | 标题行后空行删除 | 标题下一行若是空行则删除 | 开 |
| S5 | 文档首尾空行删除 | 文件开头、结尾的空行全删 | 开 |

**简化绝不合并段落**：段落之间的单个空行必须保留，否则两段会被渲染成一段，属于语义破坏。

S2 与 S3 都可能在列表块内删除空行，二者重叠执行是安全的（S2 在前、S3 在后，结果幂等）。格式化与简化是两套互不依赖的规则集，因此 F8 要求的「标题前空行」与 S4 的「标题后不留空行」不会同时生效。

## 6. 命令与快捷键

| 命令 ID | 面板名称 | 默认热键 |
| --- | --- | --- |
| `tidy-format` | Note to JSON: 格式化 | `Mod+Alt+F` |
| `tidy-simplify` | Note to JSON: 简化 | `Mod+Alt+S` |
| `tidy-json-format` | Note to JSON: 格式化 JSON | `Mod+Alt+J` |
| `tidy-json-compress` | Note to JSON: 压缩 JSON | `Mod+Alt+M` |

- 通过 `this.addCommand({ id, name, editorCallback, hotkeys })` 注册，`Mod` 在 Windows 映射为 Ctrl。
- 默认热键只作为初始值；用户在「设置 → 快捷键」搜索 `Note to JSON` 即可任意改键，插件不覆盖用户已修改的键位（Obsidian 原生行为）。
- 设置页提供「打开快捷键设置」按钮：`app.setting.open()` + `openTabById('hotkeys')`。
- 命令仅在 Markdown 视图中可用（`editorCallback` 天然满足）；无活动编辑器时不执行任何操作。

## 7. 设置项（DEFAULT_SETTINGS）

```ts
interface TidySettings {
  formatRules: Record<string, boolean>;   // F1..F10 = true，F11 = false
  simplifyRules: Record<string, boolean>; // S1..S5 = true
  codeBlockDefaultLang: string;           // 默认 ""
  showNotice: boolean;                    // 默认 true
}
```

设置页：按 `rules.ts` / `compact.ts` 导出的规则元数据（id / 名称 / 说明 / 默认值）自动渲染两组开关；再加语言输入框、提示开关、快捷键设置跳转按钮。

## 8. 错误处理与边界

| 场景 | 处理 |
| --- | --- |
| 无活动编辑器 | 静默返回 |
| 文档为空或全为保护区内容 | `Notice("已是规范格式")` |
| 处理结果与原文相同 | 不写回，按 `showNotice` 决定是否提示 |
| 文档 > 2 MB | 中止并 `Notice("文件过大，已跳过")`，避免主线程卡死 |
| 规则内部异常 | 整条管线 `try/catch`，`console.error` + `Notice("格式化失败，详见控制台")`，**原文不做任何写回** |
| 选区从行中间开始 | 起点向前扩到行首；终点向后扩到行尾（终点 ch=0 时退到上一行行尾） |
| 写回后光标 | 按行偏移重算并 `editor.setCursor` 恢复 |
| JSON 解析失败 | `Notice("JSON 语法错误（第 N 行第 M 列：片段），已保持原样")` + `console.error`，**不写回** |
| JSON 命令的作用范围 | 有选区只处理选区原文（不扩行）；无选区处理整个文件 |

## 9. 构建与安装

`esbuild.config.mjs`：`entryPoints: ['src/main.ts']`，`bundle: true`，`format: 'cjs'`，`target: 'es2018'`，`outfile: 'main.js'`，`external: ['obsidian','electron','@codemirror/*','@lezer/*']`。

`package.json` scripts：`dev`（watch）、`build`（tsc 类型检查 + esbuild）。

安装：把 `manifest.json`、`main.js`、`versions.json` 拷到 `<vault>/.obsidian/plugins/note-to-json/`，在 Obsidian 第三方插件中启用。

## 10. 验收标准

1. `npm run build` 零错误，产出单个 `main.js`。
2. 一份含 frontmatter、围栏代码块、`$$` 公式、表格、wikilink、行内代码的笔记，跑「格式化」后：保护区内容逐字节不变，表格对齐生效，标题与列表规范生效。
3. 「简化」后段落之间仍保留 1 个空行，渲染结果段落数不变。
4. 四条命令各按一次后 `Ctrl+Z` 能一步完整回滚。
5. 在「设置 → 快捷键」中能搜到四条命令并成功改键。
6. 关闭某条规则开关后，该规则不再生效，其余规则不受影响。
7. 选中一段 JSON 后「格式化 JSON」输出 2 空格缩进，`1740123456789012345` 与 `\/`、`\uXXXX` 等字面量逐字节不变。
8. 「压缩 JSON」输出单行且不含多余空白；非法 JSON 只提示错误位置、原文不变。
9. 编辑器右键菜单能看到「格式化 JSON」「压缩 JSON」，且与命令行为一致。
10. 用全角空格（U+3000）或不换行空格（U+00A0）缩进的 JSON 能被正常格式化，且字符串内部的全角空格原样保留。

## 11. 实现记录（已完成）

### 11.1 与规格的偏差（已裁决）

| 位置 | 规格原文 | 实际实现 | 原因 |
| --- | --- | --- | --- |
| F1 | `#标题` → `# 标题` | 仅在 `#` 后已有空白时压缩为 1 个空格；`#标签` 保持不动 | Obsidian 把行首 `#文字` 解析为标签（tag），补空格会把标签变成标题，属于语义破坏 |
| F10 | 列宽按单元格宽度计算 | 额外保证列宽 ≥「冒号数 + 3 个连字符」 | 否则 `:---` 会撑破列宽，分隔行比数据行宽 1 格，竖线错位 |

### 11.2 已知局限

1. 中文宽字符按 1 个字符计，纯中文表格在等宽字体下竖线不会视觉对齐（需 CJK 双宽算法）。
2. 引用块内表格（`> | a | b |`）不参与对齐与空行规范。
3. F6 以「全文最小列表缩进」为单位换算，笔记里若出现 3 空格这类异常缩进，会被折算为 1 级。
4. `#标签` 与 `#标题` 语法上无法区分，插件选择保守不动。
5. 规则会插入/删除空行，写回后光标停留在原行号（已收敛到合法范围并保留列），可能偏离原内容一两行；Ctrl+Z 仍可整体回滚。
6. 列表项内以 4 空格缩进书写的围栏（`    ```js`）不被识别为保护区（按 CommonMark 顶层规则只认 ≤3 空格缩进）；列表外的代码块不受影响。

### 11.3 部署

`npm run build` 产出 `main.js` 后，把 `manifest.json`、`main.js`、`versions.json` 复制到
`<vault>/.obsidian/plugins/note-to-json/`，在「设置 → 第三方插件」中重新加载并启用。

### 11.4 代码审查后的修复

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| Critical | 选区被当作独立文档分析，选中代码块内的行会被当正文改写 | `PipelineOptions` 增加 `prefix`（选区上方原文），pipeline 用「prefix 行 + 片段」做分析后再切回片段 |
| Important | 局部选区时 F6 用片段算缩进单位，深层列表层级被降级 | 增加 `documentText`，列表缩进单位改用整篇文档统计 |
| Important | `* * *` / `_ _ _` 水平线被 F4 / F5 改写成列表 | 新增水平线判定，F4 / F5 直接跳过 |
| Minor | F8 在标题紧邻保护区时不补空行；F3 关闭时不收敛多余空行 | F8 去掉与保护区相邻的限制，并吸收多余空行只留 1 个 |
| Minor | 写回后光标被强制归零 | 保留列位置并收敛到合法范围（行号精确映射未实现，见 11.2 第 5 条） |

## 12. JSON 格式化与压缩

### 12.1 命令与入口

| 命令 ID | 面板名称 | 默认热键 |
| --- | --- | --- |
| `tidy-json-format` | Note to JSON: 格式化 JSON | `Mod+Alt+J` |
| `tidy-json-compress` | Note to JSON: 压缩 JSON | `Mod+Alt+M` |

- 编辑器右键菜单新增「格式化 JSON」「压缩 JSON」两项，与命令共用同一个处理函数 `runJson`。
- 热键同样可在「设置 → 快捷键」中修改。

### 12.2 作用范围

- 有选区：精确处理选区原文，**不扩展到整行** —— 否则列表项 `- {"a":1}` 会把列表符号一起喂给 `JSON.parse`。
- 无选区：处理整个文件。此模式下若整篇是带 markdown 的笔记，会解析失败并报错保持原样。

### 12.3 算法：tokenizer 重排，不经过 stringify

`JSON.parse` 只用于判定合法性，返回值丢弃；输出由 `src/core/json.ts` 的 tokenizer 按原文 token 重排：

- 格式化：2 空格缩进，`{` / `[` 后换行、`}` / `]` 前退格、`,` 后换行、`:` 后一个空格；空容器 `{}` / `[]` 保持一行。
- 压缩：删除 token 之间的全部空白，输出单行。
- 数字、字符串、转义（`\/`、`\u4e2d`、`\"`）一律原样输出，因此 `1740123456789012345` 不会丢精度，`1e21` 不会被改写成 `1e+21`。
- 换行符跟随原文：CRLF 文档写回仍是 CRLF。

### 12.4 失败处理

严格 JSON：注释、尾逗号、单引号、NaN 均判为非法，弹出 `Notice("JSON 语法错误（第 N 行第 M 列：片段），已保持原样")`，`console.error` 打印引擎原始报错，**文档不做任何写回**。

### 12.5 非常规空白归一化

从网页、聊天工具或 Excel 复制来的 JSON 常在缩进里混入全角空格（U+3000）、不换行空格（U+00A0）、EM SPACE（U+2003）、零宽空格（U+200B）或 BOM（U+FEFF）。JSON 规范只认半角空格、Tab、LF、CR，这些字符会让 `JSON.parse` 报 `Unexpected token`，而报错片段 `trim()` 后看起来完全正常（典型症状：提示「第 3 行第 1 列：`"head": {`」但肉眼检查毫无问题）。

处理方式：在解析与 tokenize 之前，把**字符串字面量之外**的这些字符归一化为半角空格（零宽字符直接删除），字符串内部一个字符都不改。成功提示会附带「已修正 N 处全角/特殊空白」，让修正过程可见。

报错片段也改为可视化不可见字符（如 `⟨U+0001⟩`），避免同一种「看起来没问题却报错」的困惑。

### 12.6 取舍与局限

1. 美化后首行顶格，原本缩进在列表项内的 JSON 不还原缩进层级。
2. 不做宽松修复（去注释、去尾逗号），与 12.4 一致。
3. 顶层为标量（如 `123`、`"abc"`）时格式化等于原样输出。
4. 无选区且整篇为笔记正文时必然报错，需先选中 JSON 片段。
